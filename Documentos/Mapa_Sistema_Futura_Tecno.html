1. Qué es la plataforma

Futura Tecno combina una tienda de tecnología, una operación mayorista y un panel de administración. Hoy el catálogo está temporalmente restringido por una preinscripción para el Sorteo Bienvenida; el resto de la infraestructura de catálogo, carrito y pedidos ya existe.

Público

Pre-landing y sorteo

Registro, activación por email, declaración de pasos de WhatsApp e Instagram y validación administrativa antes de asignar el código de sorteo.

Catálogo

Productos y precios

Productos, variantes, categorías, imágenes y precios calculados desde costo, flete porcentual y margen del proveedor.

Administración

Backoffice

Importación Elit, Invid o JSON; clasificación, edición, imágenes, proveedores, usuarios, pedidos y auditoría de envíos.

Logística

Envíos y ETA

Cotización por Andreani cuando las medidas son completas y cálculo de fecha estimada considerando corte horario y feriados argentinos.

2. Arquitectura de alto nivel

3. Flujos principales de datos

Los procesos más importantes se concentran en cuatro circuitos. El backend vuelve a calcular los datos sensibles: no confía en precio ni envío recibidos desde el navegador.

Preinscripción y código de sorteo

01FormularioNombre, apellido, DNI único, nacimiento, celular, email, Instagram, contraseña y aceptación de bases.
02Cuenta + emailSe guarda el usuario, la contraseña se cifra con BCrypt y Resend envía un enlace de activación.
03Pasos declaradosEl usuario marca que escribió por WhatsApp y completó Instagram. El estado del onboarding bloquea el orden.
04Validación humanaAdmin confirma WhatsApp e Instagram; no se otorga el código sólo por pulsar “Ya lo hice”.
05Código únicoSi email, WhatsApp e Instagram están validados, se crea FT26-XXXXXXXX y se envía por email.

Importación y actualización de catálogo

01OrigenElit, Invid o JSON generado desde un listado de proveedor.
02PrevisualizarFiltros por marca/categoría/stock/precio antes de incorporar datos.
03NormalizarMarca, modelo, variante, costo, stock, categoría, código externo e imagen.
04PersistirDeduplicación por proveedor + marca + modelo; el reingreso reactiva productos previamente dados de baja.
05SincronizarJob diario 06:30 AR actualiza sólo productos existentes de mayoristas configurados.

Carrito, envío y pedido

01Carrito localEl visitante elige variante y cantidad. El carrito no es la fuente de precio.
02CotizaciónCP + medidas resueltas por producto/categoría se envían a Andreani.
03ConfirmarSe exige sesión y compromiso de compra.
04RecalcularServidor vuelve a consultar costo, margen, flete, dólar y modalidad de envío.
05Congelar pedidoGuarda precios, cotización, envío y vencimiento; avisa al administrador por email.

4. Modelo de datos y relaciones

La base usa entidades JPA con una clase base común para ID y fechas de creación/actualización. Las bajas de productos, variantes y proveedores son lógicas: se preserva el historial.

Proveedor
  • nombre, código
  • margenPorcentaje
  • fletePorcentaje
  • activo

1 Proveedor → N Productos

Producto
  • marca, modelo
  • proveedor + categoría
  • imagenUrl, fuente, código externo
  • peso / alto / ancho / largo
  • activo

1 Producto → N Variantes · N Imágenes

Variante
  • especificaciones
  • almacenamientoGb, ramGb, color
  • costoUsd, monedaOrigen
  • stock, activo

Precio público = costo + reglas del proveedor

Categoría
  • nombre
  • padre (árbol de 2 niveles)
  • peso y medidas por defecto

Se heredan medidas para Andreani

Usuario
  • email, password / googleSub
  • nombre, apellido, celular, DNI
  • rol y activo
  • estado onboarding y sorteo

1 Usuario → N Pedidos

Pedido + PedidoItem
  • número, estado, vencimiento
  • totales USD/ARS y cotización usada
  • contacto, CP y modalidad
  • ítems con precio congelado

Snapshot del pedido al confirmar

Regla de seguridad comercial: el precio de venta se calcula en backend con (costo USD × (1 + flete%) × (1 + margen%)); no se toma ningún importe enviado por el cliente.

5. Módulos y responsabilidades

Interfaz pública

Páginas React

PreLanding, BasesSorteo, Landing, Catálogo, detalle, carrito, checkout, pedidos propios, login, registro, activación y recuperación de contraseña.

Interfaz admin

Operación diaria

Dashboard, Proveedores, Productos, Categorías, Imágenes, Usuarios, Pedidos, Importar Elit, Importar Invid y Cargar por JSON.

AuthService

Identidad y sorteo

Registro, login, Google, JWT, activación de email, reset, avance de pasos y códigos de sorteo tras validación manual.

CargaJsonService

Importación manual

Convierte ArticuloJsonDTO en productos y variantes, clasifica y actualiza/reactiva coincidencias existentes.

ProductoAdminService

Calidad de catálogo

Edición individual, bajas, asignación masiva de categoría y búsqueda de imágenes mediante Icecat y Anthropic.

Elit / Invid

Mayoristas

Cada proveedor API tiene cliente y servicio de importación propios. Conviven sin mezclar sus códigos ni sus reglas de lectura.

EnvioService

Cotización logística

Resuelve medidas: producto → subcategoría → categoría padre. Si falta un dato, devuelve “a coordinar” sin quebrar checkout.

PedidoService

Pedido seguro

Revalida variantes activas, precios y envío; guarda snapshot y programa vencimiento al próximo corte operativo.

Servicios de apoyo

Precio, dólar y ETA

Cotización oficial USD/ARS cacheada, ETA por horario de corte y feriados; notificaciones por email asíncronas.

Seguridad

Capas implementadas

  • JWT stateless y filtro de autenticación.
  • Contraseñas con BCrypt.
  • Roles ADMIN / USUARIO y endpoints administrativos protegidos.
  • Validación de DNI, email y celular únicos para preinscripción.
  • Token de activación de email con expiración.
  • Precios y envío recalculados en servidor.
  • Soft delete para conservar histórico.
Jobs automáticos

06:30, hora argentina

Sincronización: actualiza precio/stock/imagen sólo de artículos ya incorporados desde Elit e Invid.

Vencimiento: marca pedidos pendientes vencidos, porque después de la sincronización sus precios o disponibilidad pueden haber cambiado.

Persistencia y deploy

Reglas operativas

PostgreSQL persiste datos en Railway. Flyway versiona el esquema mediante migraciones; Hibernate sólo valida, no modifica tablas automáticamente. Railway verifica /api/health y reinicia ante falla según la política configurada.

Importante: los secretos no van al repositorio público. Credenciales de proveedores, JWT, Meta/WhatsApp, Resend, Andreani y APIs se almacenan únicamente como variables locales ignoradas o variables de Railway.

Metodología de desarrollo y reglas que conviene mantener
  • Separación por capas: API (controladores), aplicación (reglas), infraestructura (repositorios/configuración) y dominio (entidades).
  • Todo cambio de esquema exige una nueva migración Flyway; no usar ddl-auto=update.
  • No eliminar físicamente proveedores, productos o variantes: usar activo=false.
  • Para cambios de frontend, verificar build Vite; para backend, ejecutar pruebas Maven; luego commit/push a main dispara deploy Railway.
  • Imágenes: la principal vive en Producto.imagenUrl; galería adicional en entidad Imagen.
